# Перенос бота на свой сервер

Бот, мини-приложение и база переезжают с платформы tgcloud на ваш сервер (Ubuntu или Debian).
Игровая логика та же; вместо платформы работает `server/main.js` (Node.js 24 + SQLite), HTTPS даёт Caddy.

## Что нужно
- сервер с Ubuntu 22.04/24.04 или Debian 12, от 1 ГБ памяти, открытые порты 80 и 443;
- токен бота из @BotFather;
- (по желанию) домен, направленный на IP сервера. Без домена будет адрес вида `1.2.3.4.sslip.io`.

## Шаги
1. Скачайте проект (ветка `tgcloud`) к себе на компьютер.
2. Положите выгрузку базы в `data/dump.json` (файл присылает Claude; его делают прямо перед переездом).
3. `cp deploy/server.env.example deploy/server.env` и впишите в `deploy/server.env` IP, пароль (или оставьте пустым для SSH-ключа), токен бота, домен.
4. Запустите `bash deploy/deploy.sh` (Linux, macOS или Windows через WSL).
   Скрипт скопирует проект в `/opt/carauction` и установит всё на сервере.
5. В @BotFather: `/mybots → бот → Bot Settings → Configure Mini App → URL` — адрес, который напечатает установка.

Без своего компьютера с WSL: загрузите папку проекта на сервер (например, WinSCP) в `/opt/carauction`,
создайте там `deploy/server.env` и выполните на сервере `bash /opt/carauction/deploy/install.sh`.

## Важно
- После запуска сервер отключает у бота старый вебхук tgcloud — бот работает только с вашего сервера.
  **Больше не запускайте `tgcloud push`**: платформа снова заберёт бота себе.
- Ставки и покупки, сделанные между выгрузкой и переездом, не перенесутся — выгрузку делайте прямо перед запуском.
- Обновление: снова `bash deploy/deploy.sh` (база не трогается, перед обновлением сохраняется её копия).
- Логи: `journalctl -u carauction -f`; перезапуск: `systemctl restart carauction`.
- База: `/opt/carauction/data/game.db` — делайте копии.
