# car-auction-bot

Telegram-бот-игра: аукцион контейнеров, автомобили, гараж, VIP, Battle Pass,
магазин, рефералы, промокоды и расширенная админ-панель.

**Стек:** Python 3.13+, aiogram 3, PostgreSQL, SQLAlchemy 2 (async), Alembic,
Redis, webhook (production).

## Быстрый старт

### Docker (рекомендуется)

```bash
python scripts/setup.py          # один раз: спросит токен, ваш Telegram ID, домен — создаст .env
docker compose up -d --build     # бот + PostgreSQL + Redis
```

Webhook требует HTTPS-домен, указывающий на сервер:

* **Свой прокси (nginx/Caddy)** — проксируйте `https://ВАШ_ДОМЕН/` на `bot:8080`.
* **Встроенный Caddy** с автоматическим сертификатом: `docker compose --profile proxy up -d`
  (порты 80 и 443 должны быть свободны, домен — из `WEBHOOK_DOMAIN`).

Миграции БД применяются автоматически при старте. Состояние: `GET /health`
(`200` — БД и Redis доступны, `503` — нет). Логи: `docker compose logs -f bot`.

### Без Docker

```bash
pip install -r requirements.txt
python -m app.main     # если .env нет — запустится мастер настройки
```

Нужны запущенные PostgreSQL и Redis. Для локальной разработки без домена
укажите `USE_WEBHOOK=false` (long polling — только для разработки).

## Владелец и администраторы

Владелец — пользователь с `OWNER_ID` из `.env`. Админ-панель — команда `/admin`.
Администраторов владелец назначает и снимает прямо в боте (🛡 Администраторы).
Права администратора проверяются по разделам (пользователи, машины, контейнеры,
гараж, навыки, магазин, BP, VIP, промокоды, группы, рассылки, статистика,
документация, резервные копии).

> Если вы обновляетесь с версии без раздела «Навыки», у ранее добавленных
> администраторов нет права `skills` — переназначьте их или выдайте права.

## Резервные копии

Раз в сутки (час UTC — в админке, по умолчанию 03:00) создаётся `pg_dump` и
отправляется **только владельцу**. Хранится последние N копий (по умолчанию 7) в `backups/`.

```bash
make backup                              # ручной бэкап
make restore FILE=backups/car_auction_XXXX.dump   # восстановление (бот остановить!)
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest tests/unit                      # без внешних сервисов
createdb car_auction_test              # отдельная ПУСТАЯ БД
TEST_POSTGRES_URL=postgresql+asyncpg://user:password@localhost:5432/car_auction_test pytest
```

Интеграционные тесты требуют PostgreSQL (схема в тестовой БД пересоздаётся перед
каждым тестом — не указывайте боевую БД!). Без `TEST_POSTGRES_URL` они
пропускаются. Redis подменяется `fakeredis`.

## Архитектура

`handlers` → `services` → `repositories` → PostgreSQL. Игровая логика только в
`services`, тексты только в `localization` (RU/EN), все изменяемые параметры
(цены, комиссии, таймеры, шансы, вместимость, VIP, BP, магазин, промокоды) — в БД
и меняются из админки. Redis — только блокировки, антифлуд, FSM; состояние
аукциона всегда в PostgreSQL и восстанавливается после рестарта. Все операции с
деньгами и предметами — в транзакциях с распределёнными блокировками и
уникальными ID операций; баланс не может уйти в минус (CHECK в БД).

## Известные ограничения

* **Навыки** — предмет-награда с уровнем (BP, магазин, промокод, админ); в ТЗ нет
  описания их игрового эффекта, поэтому сейчас они отображаются у игрока, но
  механику не меняют. Поле `effect` в БД зарезервировано под будущие эффекты.
* Файлы дампа больше 50 МБ в Telegram не отправляются — владелец получает
  уведомление, файл остаётся в `backups/`.
